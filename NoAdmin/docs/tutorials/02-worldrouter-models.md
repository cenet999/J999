# 第二篇：WorldRouter 模型对比速查

这篇把 `WorldRouter` 的模型列表整理成一个更适合教程阅读的版本，重点比较两类模型：

- **OpenAI GPT 系列**：适合通用对话、复杂推理、代码生成
- **国产模型**：适合成本控制、中文场景、本地化业务和多样化调用

> 说明：下面的价格单位均来自你提供的页面，统一写成 `Credits / 1M`。不同模型的价格会随平台策略变化，实际接入时请以控制台实时数据为准。

## 1. 先看怎么选

如果你只是想快速选型，可以先看这个结论：

- **追求综合能力**：优先看 `gpt-5.5`、`gpt-5.4`、`qwen3.6-plus`、`deepseek-v4-pro`
- **追求成本低**：优先看 `qwen3.5-flash`、`deepseek-v4-flash`、`glm-4.7-flash`、`mimo-v2-flash`
- **追求代码能力**：优先看 `qwen3-coder-plus`、`qwen3-coder-next`、`gpt-5.5`
- **追求中文表达和国内生态**：优先看 `qwen`、`deepseek`、`glm`、`kimi`、`MiniMax`

## 2. OpenAI GPT 模型对比

| 模型 | 定位 | Input | Output | Cache read | Cache write | 适合场景 |
|---|---|---:|---:|---:|---:|---|
| `gpt-5.5` | OpenAI | 350 | 2100 | 35 | 350 | 高要求通用推理、复杂问答、代码生成 |
| `gpt-5.4` | OpenAI | 175 | 1050 | 17.5 | 175 | 通用高质量任务，平衡能力和成本 |
| `gpt-5.4-mini` | OpenAI | 52.5 | 315 | 5.25 | 52.5 | 中等复杂度任务、轻量助手、批量调用 |

### GPT 系列怎么理解

- `gpt-5.5` 是这组里能力最强、价格也最高的选项。
- `gpt-5.4` 更适合作为日常主力模型，兼顾效果和预算。
- `gpt-5.4-mini` 适合把大量简单任务拆出去做，比如摘要、分类、初稿生成。

### 国产模型怎么理解

- **阿里 Qwen 系列**：覆盖最广，价格层次也最完整，从 `flash` 到 `coder-plus` 都有。
- **Moonshot Kimi 系列**：更偏长文本和知识类任务，中文内容处理比较顺手。
- **MiniMax 系列**：价格和能力比较均衡，适合做常规助手和生成类功能。
- **智谱 GLM 系列**：在中文场景里比较常见，适合通用问答和业务集成。
- **DeepSeek 系列**：兼顾推理和成本，是国产模型里很常见的选型对象。

## 4. GPT 和国产模型怎么对比

| 维度 | OpenAI GPT 系列 | 国产模型 |
|---|---|---|
| 综合能力 | 通常最强，尤其在复杂推理和泛化任务上很稳 | 已经很强，部分场景接近甚至足够替代 |
| 中文体验 | 可以用，但并非天然以中文业务为中心 | 通常更贴近中文表达、中文资料和国内业务习惯 |
| 价格 | 偏高，尤其是高端模型 | 选择更多，低价模型更丰富 |
| 代码能力 | `gpt-5.5` 和 `gpt-5.4` 依然很有竞争力 | `qwen3-coder-plus`、`qwen3-coder-next` 很适合开发辅助 |
| 批量调用 | 适合，但要控制预算 | 更容易按成本做大规模调用 |
| 选型建议 | 用在关键链路、核心推理、对质量要求高的环节 | 用在常规助手、中文内容、批处理、成本敏感业务 |

## 5. 一个简单的选型建议

如果你要做教程里的推荐结论，可以直接写成下面这样：

1. **高质量核心模型**：优先 `gpt-5.5` 或 `gpt-5.4`
2. **中文主力模型**：优先 `qwen3.6-plus`、`deepseek-v4-pro`、`glm-5`
3. **低成本批量模型**：优先 `qwen3.5-flash`、`deepseek-v4-flash`、`glm-4.7-flash`
4. **代码专用模型**：优先 `qwen3-coder-plus`、`qwen3-coder-next`

## 6. 教程里的写法建议

如果你准备把这张表放到教程里，建议这样组织：

- 先写一句结论，告诉读者“为什么要对比模型”
- 再放一张总表，快速区分 GPT 和国产模型
- 再拆成两张详细表，方便读者查价格和定位
- 最后补一个“怎么选”的建议段落，帮助读者落地

这样读起来会比直接贴一大串模型列表更清楚，也更像教程，而不是原始后台清单。
